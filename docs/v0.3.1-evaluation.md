# Aporic 0.3.1 evaluation checkpoint

This checkpoint records implementation evidence for the `0.3.1` release. It is not a production-security claim.

## Source-build setup behavior

- Source-build documentation distinguishes the Rust toolchain needed to create the plugin package from the bundled binary used after packaging.
- The packager checks for both `cargo` and `rustc` before creating its output directory.
- When Homebrew's keg-only `rustup` proxy directory exists but is absent from `PATH`, the diagnostic gives the exact `~/.zprofile` entry and retry sequence.
- Other missing-toolchain cases receive a Rust 1.89-or-newer installation diagnostic.

## Verification environment

- The focused missing-toolchain packaging regression test passed.
- The full suite passed 85 tests with the local stable Rust 1.98.1 toolchain.
- The same 85 tests passed with the declared minimum Rust 1.89.0 toolchain.
- `cargo fmt --all --check` passed after formatting.
- `cargo clippy --all-targets --locked -- -D warnings` passed.
- A fresh optimized macOS arm64 plugin package passed the Codex plugin validator and retained plugin version `0.3.1`.
- An independent read-only review found no release blocker; its only residual test-coverage note was resolved by asserting that the missing-toolchain diagnostic includes an actionable Homebrew or generic rustup recovery path.

## Residual boundaries

- Aporic does not publish prebuilt release artifacts; creating the plugin package still requires a source build.
- The packaged host remains macOS arm64 only.
- Hook trust and plugin replacement remain Codex host state and require a new task after installation.
