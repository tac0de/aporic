# Aporic 0.7.0 evaluation

## Acceptance surface

- Event schema v5 replays caller-declared structured intent envelopes with distinct explicit, inferred, and unknown items without requiring raw prompt storage.
- New plans may bind one active same-scope intent envelope; dangling, cross-scope, and already superseded bindings are rejected.
- Superseding an intent requires a distinct active same-scope replacement and a human-declared event.
- Plan authorizations and execution grants bound to a superseded intent stop satisfying the action gate without rewriting historical events.
- New authorization, grant, and completion events for a stale bound plan are rejected.
- Legacy unbound plans remain replayable after explicit non-destructive v1, v2, v3, or v4 migration to schema v5.
- Projection schema v6 exposes active intent envelopes within the existing deterministic UTF-8 byte budget and reports retained and omitted intent counts.
- Policy schema v2 can require active intent-bound plan authority per exact tool, while schema-v1 policies decode `require_intent` as false.
- Fresh project bindings enable `require_intent` for `apply_patch`; invalid intent-only policies without plan or grant enforcement are rejected.
- `PostToolUse` records an idempotent effect receipt without raw input or response values and never promotes a tool-specific response to success.
- Verifier report schema v1 binds one separately produced result to an existing same-scope receipt, plan check, and direct evidence record.
- Unknown, cross-scope, inference-only, non-Evidence-authored, and conflicting verifier reports are rejected; the latest accepted result participates in completion.
- One static capability registry drives MCP listing and dispatch for exactly four tools. Three are read-only; verifier-report ingestion is the sole state write and is approval-prompted by the plugin package.
- MCP messages are bounded, unknown methods and tools fail closed, project access requires an absolute explicit workspace binding, and no authority or arbitrary-commit operation is exposed.

## Verification

Run:

```console
cargo fmt --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
jq empty schemas/*.json packaging/codex-plugin/hooks/hooks.json packaging/codex-plugin/.codex-plugin/plugin.json packaging/codex-plugin/.mcp.json
```

Focused regression coverage lives in `tests/v070.rs`, `tests/v070_effects.rs`, and `tests/mcp.rs`. These checks establish deterministic lifecycle, migration, receipt, verifier-ingestion, bounded MCP dispatch, and read-only behavior; they do not authenticate the recorded actor, prove that a model interpreted natural language correctly, independently execute a verifier, or cryptographically attest to the eventual tool effect.

Intent binding remains policy-selectable. Fresh project bindings require it for `apply_patch`, while migrated schema-v1 policies and v2 tools configured with `require_intent: false` preserve legacy behavior without inventing lineage for historical records.

Release operations must preserve the pre-migration store, validate the packaged plugin, and keep external publication behind an explicit confirmation at the publication boundary.
