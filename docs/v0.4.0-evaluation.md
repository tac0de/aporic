# Aporic 0.4.0 evaluation checkpoint

This checkpoint records implementation evidence for the `0.4.0` development release. It is not a production-security or natural-language-understanding claim.

## Intent-fidelity boundary

- A bound-project `UserPromptSubmit` hook adds a language-neutral advisory on every user turn.
- The Rust adapter validates the documented hook shape and project binding but does not interpret, persist, hash, echo, or block the prompt.
- The advisory is deterministically bounded to 1,200 UTF-8 bytes and cannot authorize a plan or tool call.
- Existing event schema v2, projection schema v3, store compatibility, and `PreToolUse` evaluation remain unchanged.
- Unbound projects receive only `{ "continue": true }`; invalid project discovery warns while configured tool gates retain their independent behavior.

## Verification environment

- Focused Codex adapter, CLI, and packaging tests cover bounded output, prompt non-disclosure, exact hook shape, opt-in discovery, invalid bindings, and packaged hook registration.
- `cargo test --locked` passes 92 tests on the development toolchain.
- `rustup run 1.89.0 cargo test --locked` passes the same 92 tests on the declared minimum Rust toolchain.
- `cargo clippy --all-targets --locked -- -D warnings` and `cargo fmt --all --check` pass.
- A fresh macOS arm64 release package builds successfully and passes the Codex plugin validator.
- Independent read-only review found no P0-P2 issue. Its P3 oversized-input finding was resolved by bounding raw `UserPromptSubmit` input to 1 MiB and skipping only the advisory when exceeded.

## Residual boundaries

- The advisory does not prove that the model preserved intent or resolved Korean correctly.
- Intent is not stored, versioned, linked to a plan, or used as an execution gate in this release.
- Demonstrated Korean quality improvement requires a matched evaluation with a Korean-speaking reviewer in the independently versioned `korean-intelligence` plugin.
- Hook trust and plugin replacement remain Codex host state and are not performed by this source update.
